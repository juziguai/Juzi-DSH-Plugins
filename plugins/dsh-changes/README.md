# 变更 · @juzi/dsh-changes

在 DSH 右侧查看当前会话的文件变更。执行中约每秒刷新，按轮次比较“本轮开始时”与“当前/结束时”的内容，显示文件状态、增删行数和统一差异。只保留本次 Host 运行期间的数据。

## 使用

- 会话标题右侧点击「变更」，或在右侧面板的添加页选择「变更」。
- 默认跟随当前/最近一轮；可选择上一轮或具体历史轮次。阅读历史时不会被新一轮抢走选择。
- 文件使用同一条紧凑标题行显示目录、文件名、增删行数、打开文件和更多操作。点击文件名在原位展开或折叠差异，展开前后标题位置和布局保持一致；没有重复的顶部导航或独立卡片标题。
- 顶部更多菜单提供「自动换行」和「展开全部差异 / 折叠全部差异」。默认自动换行，切换文件和轮次后继续沿用选择；全部展开覆盖当前列表，并跟随本轮新增文件。手动选择轮次后重新从折叠状态开始。
- 顶部「复制变更摘要」将所选轮次当前显示的状态、文件列表与增删统计复制为 Markdown，不读取文件正文。执行中的摘要注明截至复制时；重命名保留旧路径，二进制、超限、列表截断和记录异常会明确标注。复制成功显示提示，剪贴板不可用或被拒绝时显示失败原因。
- 差异按可见区域读取；远离可见区域时释放差异正文并保留滚动占位，折叠或隐藏面板时取消待完成的差异请求，避免一次拉取全部文件。
- 文件行可打开当前文件，更多菜单可展开或折叠；按 Esc 折叠当前差异并返回对应文件标题。差异使用单列行号和红绿增删标记，保留修改附近的上下文，其余未修改区段以行数提示省略。已删除文件不能打开当前文件；已结束轮次如有官方记录，可打开官方轮次对比。
- 建立基线会先完成，再允许该轮 Agent 工具执行。轮前未提交的修改不会作为本轮结果列出。
- 面板隐藏时停止请求与快照刷新，文件监听只标记脏状态；再次打开时读取最新内容。轮次结束会生成最终快照，即使未打开面板也有最终记录。
- 会话和所有已记录轮次均结束后停止定时查询。新轮开始、工具完成、工作区变更与连接重置会触发合并刷新；执行中继续约每秒读取，因此长时间工具内部的写入仍会更新。流式文本和加载更早的历史不会触发文件查询。
- 停用或热替换本插件会释放当前临时记录；聊天和工作区文件保留，需留档时先复制变更摘要或导出差异。

## 覆盖边界

- 有 Git 仓库：覆盖 Git 跟踪及未忽略文件，包括 shell 和外部进程在该轮期间的修改。
- 忽略文件、工作区外路径：仅覆盖被 DSH 文件编辑工具明确修改的目标，并在实际写入前捕获原始内容。
- 非 Git 目录：需要本机 Git 作为私有快照引擎，但只记录文件编辑工具点名的文件，不能捕获仅由 shell 修改的文件；界面会提示。
- 子代理独立会话不单独记录；在相同工作区产生的修改可进入父会话的快照，无法据此区分具体写入者。嵌套仓库和 submodule 的内部修改不在 Git 文件列表内，只有被文件编辑工具点名的目标能补充记录。
- 同时由用户或其他 Agent 修改同一工作区时，显示的是该轮期间的工作区变化，不宣称全部来自当前 Agent。轮次结束后的后台进程写入不追溯到已冻结的轮次。
- 不恢复安装前或 Host 重启前的历史；会话释放后保留已记录的轮次以便本次运行期间重新查看。插件释放或 Host 正常退出时清理临时数据；强制结束 Host 可能留下 `juzi-dsh-changes-*` 和 `juzi-dsh-blobs-*` 临时目录，不会加载为历史。
- 二进制、非 UTF-8 文本和超限文件只列状态，不显示文本。单个差异页面最多绘制 5,000 行。

## 运行与数据

需要 DSH 0.2.1-rc.3 或更新版本、本地文件系统，以及可通过 DSH `subprocess` 服务找到的 Git（支持 `git init --object-format=sha1`）。文件监听使用本地 Node `fs.watch`，不支持将远程工作区伪装成本地路径；监听失败时显示提示，并在工具结果或手动刷新后更新。

每轮使用独立临时 Git 树和索引，文件内容按哈希共享到本次 Host 的私有 blob 库；最后一个引用该内容的轮次释放时回收。每轮仍在工具执行前核对文件列表和元数据，未变文件复用内容，未变的树不重建索引。不执行用户仓库的 `git add`/提交，不改用户 index、ref 或对象库，不调用仓库 clean/smudge 过滤器。插件自己的摘要/差异 GET 路由注册在 DSH Connection 的认证边界内；只接受已记录的会话、轮次、文件 ID 和修订号，不接受任意读取路径，不注册模型工具。

配置通过本插件自己的校验器验证，示例：

```yaml
- id: juzi-changes
  config:
    refreshMs: 750
    timeoutMs: 15000
    maxFiles: 500
    maxFileBytes: 2097152
    maxSnapshotBytes: 134217728
    maxStoredBytes: 536870912
    maxTrackedFiles: 20000
    maxTurns: 30
```

`refreshMs` 至少 250ms，所有配置均为正整数。`maxFiles` 限制单次列表，汇总仍包含全部变更。`maxSnapshotBytes` 限制一次扫描读取的新内容总量，超过时文件以超限状态列出。`maxStoredBytes` 为该插件本次运行所有会话去重后的原始内容预算；达到上限时保留已有记录并明确显示错误，结束本次运行后清空。每个会话默认保留最近 30 轮，清理旧轮次时释放不再被其他轮次引用的内容预算。

## 开发验证与安装

维护入口为 `lib/index.js`（事件与路由）、`lib/recorder.js`（快照生命周期）、`lib/git.js`（Git 接缝）、`lib/client.js`（右侧页面）。客户端自包含，只依赖宿主的 React 与公开侧栏/插槽契约，不依赖 Ultra。

```powershell
node --test scripts/changes*.test.mjs
npm test
git diff --check
```

在隔离 profile 安装包后发起一个新轮次，分别验证文件编辑、长时间 shell 写入、查看历史、切换会话和隐藏面板。源码检查通过不等于真实客户端验收。安装沿用 DSH 插件流程，默认配置无需修改现有官方插件；本仓库不会自动改生产 profile 或重启客户端。
