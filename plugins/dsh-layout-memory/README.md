# 布局记忆

记住 DSH 左右侧栏的宽度，在页面刷新、冷启动或布局模块重新加载后恢复。同一本机配置中的会话共用一套偏好，不同步到其他设备。

首次启用采用当前有效宽度；以后拖动侧栏即可更新记录。宽度按 CSS 像素保存，窗口变小时由宿主的原生动作限制，重新变大时恢复原偏好。展开/收起、右侧标签页、全屏、会话选择和应用窗口尺寸仍由 DSH 管理；恢复宽度不会主动打开侧栏。

## 兼容与实现

最低 DSH 版本为 0.2.1-rc.3，本次验收基线为 Windows 桌面版 0.2.1-rc.3。通过公开 `slots.entries('root')` 取得当前根布局的共享 Store，订阅快照并调用原生 `setSidebar` / `setRightbar`；不修改 DSH 安装包，不替换根组件，不依赖 React 内部字段或 DOM 轮询。

宽度字段仍属于当前宿主布局契约。根 Store 不再共享、字段/动作不兼容时停止接管并告警一次；需要对新的宿主版本重新验收。当前契约的左栏范围为264–420 CSS px，右栏最小300、最大为窗口宽度的70%（下限不足时取300），实际可见区域继续由DSH计算。

独立存储键为 `localStorage['juzi.layout-memory.v1']`，仅包含版本和两个宽度值，不保存聊天内容、标签或窗口坐标。普通写入合并到200ms后，页面退出及插件停用时补写。关闭侧栏保存其最后非零偏好；隐藏、全屏或临时窗口限制不会覆盖偏好。

记录损坏、版本不识别或存储不可用时，不修改该记录，停止该布局实例的接管并在日志告警。重置时只删除 `juzi.layout-memory.v1` 这个键，然后重新启用插件；不要清空DSH其他本地数据。多个窗口不实时同步，后一次宽度写入用于下次启动恢复。

## 构建、测试与安装

源码为 `lib/memory.js` 和 `src/client.mjs`，`lib/client.js` 由构建生成：

```powershell
npm run layout:build
node --test scripts/layout-memory.test.mjs
npm test
git diff --check
```

Host入口为空，浏览器依赖宿主布局插件，没有新增运行时第三方依赖、MCP或收费API。测试可额外设置 `DSH_SLOT_CORE_MODULE` 使用官方SlotCore；`DSH_LAYOUT_SHARES_MODULE`、`DSH_LAYOUT_SOURCE_FILE` 与现有的 `DSH_ULTRA_UI_RUNTIME_ANCHOR` 用于安装版前端的隔离集成验证，不会操作真实Profile。

在DSH「插件 → 发现」刷新橘子插件市场，选择「布局记忆」0.1.0安装；也可通过DSH插件管理器安装Release附件中的独立tgz。市场索引固定到已提交的源码版本，发布包与本地开发包独立生成。

## 停用与回滚

停用会解除全部订阅、事件和定时器，并保留当前宽度和本地记录。停用后下次冷启动恢复DSH原有默认布局，重新启用则恢复保存的宽度。卸载只移除此插件；回滚配置前应正常退出DSH，并保留部署以后产生的其他配置变更。

验收入口：先调窄右栏并调整左栏，确认没有运行中的任务，正常退出再打开DSH；同样窗口大小下，两侧宽度与退出前相差不超过1 CSS px，面板开关与标签仍由DSH自行恢复。
